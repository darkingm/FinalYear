# 4. Frontend-driven Transaction Model

Flow:

1. FE requests quote
2. API returns calldata + price window
3. FE builds tx
4. User signs in wallet
5. Tx broadcast
6. FE gets txHash
7. FE posts txHash
8. Backend tracks tx
9. Indexer confirms
10. Saga updates order

---

# 5. Saga Orchestration Model

States:

```
UNPAID
→ TX_SUBMITTED
→ ONCHAIN_PENDING
→ ONCHAIN_CONFIRMED
→ PAYMENT_VALIDATED
→ PAID
→ DELIVERING
→ COMPLETED
```

Compensation:

* TX_FAILED → revert order
* PAYMENT_INVALID → refund flow
