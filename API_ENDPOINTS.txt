1. AUTHENTICATION & USERS
========================================

## Auth Service (Port 3001)

POST /api/v1/auth/register
- Register new user
- Body: { email, username, password, fullName }

POST /api/v1/auth/login
- Login with email/password
- Body: { email, password }
- Returns: { accessToken, refreshToken, user }

POST /api/v1/auth/verify-email
- Verify email with OTP
- Body: { email, otp }

POST /api/v1/auth/refresh-token
- Refresh access token
- Body: { refreshToken }

POST /api/v1/auth/logout
- Logout user
- Body: { refreshToken }

GET /api/v1/auth/google
- Start Google OAuth flow

GET /api/v1/auth/facebook
- Start Facebook OAuth flow

## User Service (Merged into Auth Service)

GET /api/v1/users/profile

- Requires: Authentication

- Update user profile
- Requires: Authentication
- Body: { fullName, bio, phone, etc }

GET /api/v1/users/:id
- Get user by ID (public view)

GET /api/v1/users/search?q=username
- Search users

========================================
IMPORTANT CONCEPTS
========================================

## Wallet System

1. USER WALLETS (Symbolic)
   - Stored in: wallets table
   - Purpose: Track user balances on platform
   - These are NOT real blockchain balances
   - Example: User has "1.5 BTC" on platform

2. ADMIN WALLET (Real)
   - Stored in: wallets table (special ID: 00000000-0000-0000-0000-000000000001)
   - Purpose: Hold REAL coins on blockchain
   - Admin wallet must have enough real coins to cover all user symbolic balances
   - Example: If users have total 10 BTC symbolic, admin should have 10+ BTC real

3. Deposit Flow:
   a. User sends real BTC to admin address
   b. Admin confirms blockchain transaction
   c. POST /api/v1/admin/wallets/deposits/process
   d. System increases both: admin real balance AND user symbolic balance

4. Withdrawal Flow:
   a. User requests withdrawal
   b. POST /api/v1/wallets/withdraw
   c. Admin processes: POST /api/v1/admin/wallets/withdrawals/process
   d. System decreases both: user symbolic balance AND admin real balance
   e. Admin sends real coins to user's address

5. Liquidity Health:
   - GET /api/v1/admin/wallets/platform/health
   - Checks if admin has enough real coins
   - Status: healthy (100%+), warning (80-100%), critical (<80%)

========================================
AUTHENTICATION
========================================

All protected routes require:
Header: Authorization: Bearer <accessToken>

API Gateway extracts user info and forwards as headers:
- X-User-Id: User ID
- X-User-Role: User role (ADMIN, SELLER, USER, SUPPORT)
- X-User-Email: User email
- X-User-Username: Username

========================================
ERROR HANDLING
========================================

All endpoints return consistent format:

Success:
{
  "success": true,
  "data": { ... },
  "message": "Operation successful"
}

Error:
{
  "success": false,
  "error": "Error message",
  "details": "Additional info"
}

Status Codes:
- 200: Success
- 201: Created
- 400: Bad request / Validation error
- 401: Unauthorized
- 403: Forbidden
- 404: Not found
- 500: Server error
- 503: Service unavailable
