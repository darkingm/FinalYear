💰 WALLET SYSTEM EXPLAINED
========================================

## Concept: Symbolic vs Real Balances

### User Wallets (Symbolic)
- Stored in database (wallets table)
- NOT real blockchain balances
- Just numbers representing user's platform balance
- Example: User sees "5.0 BTC" in their wallet

### Admin Wallet (Real)
- Special wallet ID: 00000000-0000-0000-0000-000000000001
- Holds REAL coins on blockchain
- Admin must maintain sufficient liquidity
- Example: Admin holds real 50 BTC to cover all users' symbolic balances

### How It Works

1. User Deposit:
   - User sends 1 BTC to admin's BTC address
   - Admin confirms transaction on blockchain
   - Admin calls: POST /api/v1/admin/wallets/deposits/process
   - System adds:
     * +1 BTC to admin real balance
     * +1 BTC to user symbolic balance

2. User Withdrawal:
   - User requests withdrawal of 0.5 BTC
   - User calls: POST /api/v1/wallets/withdraw
   - Admin processes: POST /api/v1/admin/wallets/withdrawals/process
   - Admin sends real 0.5 BTC to user's address
   - System deducts:
     * -0.5 BTC from user symbolic balance
     * -0.5 BTC from admin real balance

3. User-to-User Transfer:
   - User A transfers 0.1 BTC to User B
   - Symbolic balances update:
     * User A: -0.1 BTC
     * User B: +0.1 BTC
   - Admin real balance: NO CHANGE (still on platform)

## Admin Responsibilities

1. **Maintain Liquidity**
   - Monitor: GET /api/v1/admin/wallets/platform/health
   - Ensure admin real balance >= total user symbolic balance
   - Status indicators:
     * Healthy: 100%+ coverage
     * Warning: 80-99% coverage
     * Critical: <80% coverage

2. **Sync Real Balances**
   - Regularly check blockchain
   - Update: POST /api/v1/admin/wallets/sync
   - Recommended: Every hour or on-demand

3. **Process Withdrawals**
   - Monitor pending withdrawals
   - Send real coins on blockchain
   - Confirm: POST /api/v1/admin/wallets/withdrawals/process

========================================
🔐 SECURITY
========================================

1. **Passwords**
   - All stored with bcrypt (salt rounds: 10)
   - Minimum length: 8 characters

2. **JWT Tokens**
   - Access token: 7 days
   - Refresh token: 30 days
   - Tokens blacklisted on logout

3. **Rate Limiting**
   - Protects against brute force
   - Different limits for different endpoints

4. **Admin Wallet Private Keys**
   - NEVER store in database unencrypted
   - Use hardware wallet or HSM
   - Only admin knows private keys

========================================
🔧 TROUBLESHOOTING
========================================

## Issue: "Wallet not found"
Solution: Create wallet first
```
POST /api/v1/wallets
Body: { "coinSymbol": "BTC" }
```

## Issue: "Insufficient balance"
Solution: Check user's available balance (not locked)
```
GET /api/v1/wallets/:coinSymbol
```

## Issue: "Admin wallet insufficient real balance"
Solution: Sync admin wallet from blockchain
```
POST /api/v1/admin/wallets/sync
Body: { "coinSymbol": "BTC", "realBalance": <actual_balance> }
```

## Issue: Database connection failed
1. Check PostgreSQL is running
2. Verify port and password
3. Check DATABASE_URL in .env

## Issue: Service unavailable (503)
1. Check if all services are running
2. Check service URLs in api-gateway/config/services.ts
3. Verify network connectivity
